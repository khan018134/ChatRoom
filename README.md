# ChatRoom

ChatRoom is a small anonymous, one-to-one chat application. It uses an Express
HTTP server and Socket.IO for ephemeral identities, random matchmaking, private
pair rooms, messages, typing indicators, and disconnect cleanup. Messages and
accounts are not stored.

The interests and etiquette shown in the sidebar are static UI content; matching
does not currently use interests. This project does not provide user accounts,
moderation/reporting, message persistence, or end-to-end encryption.

## Technology

- Node.js 18 or later
- Express 5
- Socket.IO 4
- A single HTML/CSS/JavaScript frontend

## Prerequisites and install

Install Node.js 18 or later, which includes npm. From PowerShell in the project
folder, install the exact dependency versions in the lockfile:

```powershell
npm ci
```

## Start and access

Start the server:

```powershell
npm start
```

The default port is `3000`. Open <http://127.0.0.1:3000> on the host PC. The
server binds to `127.0.0.1` by default and is reachable only from that PC.

Optional environment variables:

| Variable | Default | Purpose |
| --- | --- | --- |
| `PORT` | `3000` | HTTP and Socket.IO listening port (1-65535). |
| `HOST` | `127.0.0.1` | Bind address. Set to `0.0.0.0` to opt in to LAN access. |
| `ALLOWED_ORIGINS` | empty | Comma-separated exact `http://` or `https://` origins for additional cross-origin clients. Same-origin clients are allowed by default. |

Example PowerShell configuration for a host-only server on another port:

```powershell
$env:HOST = "127.0.0.1"
$env:PORT = "3100"
npm start
```

Stop the server with **Ctrl+C** in its terminal. To restart it, run `npm start`
again. Environment variables set in PowerShell apply only to that terminal
session.

### Same-Wi-Fi/LAN access

1. Start the app with `HOST` set to `0.0.0.0` to opt in to LAN access:

   ```powershell
   $env:HOST = "0.0.0.0"
   npm start
   ```

2. On the host PC, run `ipconfig` and find its IPv4 address on the active Wi-Fi
   or Ethernet adapter.
3. On another device on the same trusted network, open
   `http://<host-ipv4-address>:3000`.
4. If Windows Firewall blocks the connection, allow the selected port for the
   Node.js app on the **Private** network profile only if you intend to share
   this chat with devices on that LAN. Do not enable a Public-profile rule or
   configure router port forwarding for this project.

Binding to `0.0.0.0` makes the service listen on available network interfaces;
it does not itself configure a firewall or expose the app through your router.
Use it only on a trusted private network. The app does not provide TLS or user
authentication.

## Tests

Run the automated server and Socket.IO integration tests:

```powershell
npm test
```

The tests cover the HTTP page and security headers, private matchmaking and
message isolation, malformed/empty/oversized messages, rapid message limits,
queue cleanup, disconnect/leave behavior, and rejection of a foreign socket
origin.

## Troubleshooting

- **`EADDRINUSE`**: Another process is using the configured port. Stop that
  process or set `PORT` to an unused port, then restart.
- **Page does not load**: Confirm `npm start` is running and use the matching
  port in the browser URL.
- **LAN device cannot connect**: Confirm both devices are on the same trusted
  network, `HOST` is set to `0.0.0.0`, and Windows Firewall permits the port on
  the Private profile.
- **Socket connection is rejected**: Keep the page and Socket.IO on the same
  origin, or add the exact frontend origin to `ALLOWED_ORIGINS` (comma-separated
  when there is more than one).

## Security and deployment notes

The server only serves the chat page; project files such as `server.js`,
`package.json`, and the unrelated `tailwind.html` snapshot are not exposed as
static assets. Socket.IO checks request origins, validates message payloads and lengths, rate-limits
matchmaking/messages/typing events, and sends messages only to the server-owned
pair room. The frontend renders chat content as text.

Socket state and matchmaking queues are held in memory in one server process.
Restarting the process ends all active sessions. This is intended for local or
trusted-LAN use, not public deployment.
